На устройстве: открыть обычный фильм с постером → Смотреть/Источники → Гульки → The Pirate Bay → проверить запрос, результаты, возврат назад, качество и запуск файла через TorrServer.

# Обновление 0.2.0 — The Pirate Bay

19 автоматических тестов прошли. Добавлены проверки формирования URL без ключа, преобразования info_hash в magnet, категорий фильмов, IMDb ID, пустого ответа, повреждённых данных, нативного Android-транспорта (подмена API), отмены, тайм-аута и повторного подключения без дубликатов.

Реальный GET к `https://apibay.org/q.php` с запросом `big buck bunny` и категориями `201,202,207,209,210,211` вернул HTTP 200 и 12 результатов. Все 12 обработаны адаптером в записи с magnet. Торренты не загружались, воспроизведение не запускалось. В ответе на запрос с Origin `https://lampa.mx` отсутствовал заголовок Access-Control-Allow-Origin: работа через обычный браузерный XHR не подтверждена и может блокироваться CORS.

Endpoint и категории сверены с https://thepiratebay.org/static/main.js . Нативный сетевой интерфейс сверён с https://github.com/yumata/lampa-source/blob/main/src/utils/reguest.js . Для запросов используется только JSON endpoint; HTML и рекламные скрипты сайта плагин не загружает.

На устройстве: перезапустить Lampa → Гульки → The Pirate Bay — поиск без ключа → ввести название фильма → открыть качество и раздачу → проверить файлы и воспроизведение через настроенный TorrServer. Существующие настройки парсера не должны измениться. Нативная сеть и воспроизведение на реальном Android TV ещё требуют проверки.

Автоматически: 11 тестов прошли в Node через доступную среду исполнения JavaScript. В системном shell Node отсутствует; команда `node tests/run.cjs` предназначена для компьютера с установленным Node.

Проверены нормализация Jackett, извлечение качества/года, объединение и удаление повторов, разделение ремейков и записей без года, фильтры, отклонение небезопасных ссылок, кодирование запроса и ключа, частичный отказ источников, неверная схема ответа, отсутствие источников. Проверен путь меню → поиск → каталог → качество → вызов `Lampa.Torrent.start` на подменённых API Lampa/XHR, отсутствие записи в действующие настройки парсеров и повторная загрузка плагина.

Это тесты с фикстурами и подменами API, не запуск Lampa. Реальных серверов, учётных данных, телевизора и репозитория GitHub в рабочей папке нет. CORS, авторизация, доступность раздач, воспроизведение и управление физическим пультом не проверены.

## Проверка на устройстве

1. Запишите текущие настройки Jackett/JacRed. Установите plugin.js по URL Pages, перезапустите Lampa, убедитесь, что пункт «Гульки» появился один раз.
2. Добавьте свой Jackett, найдите известное название. Проверьте, что неправильный ключ даёт ошибку, а другие источники продолжают возвращать результаты.
3. На своём JSON-источнике с одинаковым movieId и разными качествами проверьте одну карточку фильма, фильтры, выбор качества и раздачи. Проверьте переход между страницами, кнопки назад и отмену долгого запроса.
4. С законно доступной тестовой раздачей и настроенным TorrServer выберите раздачу. Убедитесь, что Lampa показывает реальные файлы, выбранный файл воспроизводится и перематывается.
5. Отключите TorrServer, повторите выбор: сообщение об ошибке должно появиться в штатном интерфейсе Lampa. Верните доступность сервера и повторите.
6. Сравните исходные настройки парсеров; отключите плагин и проверьте прежний поиск.
7. Проверьте после перезапуска сохранение источников и очистку каталога в памяти. Для удаления локальных ключей удалите источники в интерфейсе до отключения плагина.
